# 事件、政策与竞争学校

[返回 README](../README.md) · [学生与传承](03-students-and-legacy.md) · [技术设计](08-technical-design.md)

事件系统应把已有决策的后果呈现出来，而不是用随机弹窗代替经营。普通事件允许玩家预防或恢复，重大变化提前告知适用时间和影响范围。

## 1. 事件分类与调度

| 类别 | 触发来源 | 默认交互 |
|---|---|---|
| 日历事件 | 开学、拨款、报名、比赛、毕业 | 固定时间提醒或强制日程 |
| 状态事件 | 疲劳、学业、设备、财务达到条件 | 先预警，再提供行动 |
| 关系事件 | 具体学生、家长、学长、外校互动 | 呈现诉求与承诺 |
| 世界事件 | 政策、考纲、市场、评测环境变化 | 公告、准备期、生效日期 |
| 风味事件 | flag、拜神、小卖部、机房日常 | 气泡或日志，通常不打断 |
| 事件链 | 先前抉择、承诺和结果 | 以状态和明确标记推进 |

每次在标准日或指定时段边界检查触发器，不按渲染帧检查。筛选候选时先应用资格、冷却、互斥与当期上限，再使用事件独立随机流选择。

默认草案：每学年 3～6 个主要随机抉择，重要日历决策不占这一额度；普通随机抉择至少间隔 14 个标准日。危急状态和既有事件链后续不受随机额度限制，但合并同源提醒。风味消息每日最多 3 条，超出进入日志。

同一边界最多呈现一个模态抉择；其余排队，优先级为健康与比赛事故、即将截止的事项、承诺事件、普通抉择、风味消息。同一事件实例只能存在一个未解决节点。后续事件最早下一个逻辑边界触发，每边界执行数设上限，避免递归循环。

## 2. 事件契约

事件配置需要有稳定 ID、版本、适用阶段、触发条件、对象范围、优先级、冷却、互斥组、选项、成本、效果、后续与失败回退。

- 触发条件只读当前模拟快照，不修改世界状态。
- 打开弹窗不应用效果；确认选项时再次校验对象与资源。
- 效果由白名单操作组成，如属性增减、资金支出、设置标记、安排后续；不执行任意代码或系统命令。
- 每个实例有独立 instance_id，选项确认生成唯一事务 ID；重复点击和读档不重复扣费。
- 目标学生离队、设备已出售或政策失效时，节点取消或执行预设替代分支，不留下无法关闭的弹窗。
- 不允许确认的付费选项必须显示缺少的资源，并至少提供一个无需额外资金的可行选择。

### 2.1 合法 JSON 示例

以下条件与效果的操作名构成提议的数据契约，未来实现时应通过 schema 校验；当前仓库尚无解析器。

~~~json
{
  "id": "evt_student_burnout_warning",
  "version": 1,
  "scope": "student",
  "phase": "slot_end",
  "priority": 80,
  "cooldown_standard_days": 30,
  "exclusive_group": "student_wellbeing",
  "conditions": [
    { "path": "student.lifecycle", "op": "eq", "value": "active" },
    { "path": "student.burnout", "op": "gte", "value": 60 }
  ],
  "text": "最近训练时，总感觉脑子转不动了。",
  "choices": [
    {
      "id": "reduce_load",
      "text": "先调整后续三天的训练计划",
      "costs": [],
      "effects": [
        { "op": "set_flag", "target": "student", "key": "rest_plan_requested", "value": true }
      ],
      "follow_up": { "event_id": "evt_rest_plan_review", "delay_standard_days": 7 }
    },
    {
      "id": "hear_concerns",
      "text": "先听听具体困难，暂不改动课程",
      "costs": [],
      "effects": [
        { "op": "set_flag", "target": "student", "key": "wellbeing_followup_required", "value": true }
      ]
    }
  ],
  "on_target_missing": "cancel_with_log"
}
~~~

选择“调整计划”只生成待确认的排课修改，不立即恢复体力，也不绕过已锁定赛事。实际收益来自执行休整；7 日后检查是否兑现，未排课或未执行会形成失约记录。

总览中的名额游说 JSON 仅演示剧情效果，正式事件统一采用本篇的条件与操作列表，并继续校验名额规则。

## 3. 事件链样例

### 3.1 差一点获奖

入口：同一学生连续两场重要赛事距奖项线不超过 5 分，且不是评测事故造成。

1. 学生提出怀疑自己是否适合竞赛，显示两场实际失分构成。
2. 玩家可安排针对性复盘、下调短期目标、先休整，或暂不调整。
3. 7～14 个标准日后，检查对应行动是否完成；空口鼓励不等于行动。
4. 下一场比赛按真实能力与状态结算。事件可以改善信心，不保证逆袭或强制获奖。
5. 无论留队或退役，都保留本人选择与教练回应，作为校史片段。

### 3.2 旧机房的夏天

入口：连续高温、设备散热差且故障率上升；先显示维护预警。

选项包括付费维护、错峰训练、借用教室安排纸笔课。继续高负荷运行会提高已有故障风险，但不得为了制造剧情固定使玩家比赛当天必定停电。

若后续完成升级，校史可以记录“第一台空调 / 第一次暑期改造”；设备耐久恢复由实际维修事务产生。

### 3.3 学长的一堂课

入口：学长愿意回校且具有对应知识；生成可协商的空闲日期。

邀请会占用教室与负责人安排。学生未满足前置知识时收益降低；正式排课后才产生教学收益。放弃邀请不扣永久声誉，改期受学长时间限制。

### 3.4 承办中的换机争议

入口：比赛中一名选手机器故障，备用机可用。

提供统一换机、按记录核定补时、联系裁判等操作；不提供“只照顾本校但不算违规”的捷径。反馈先记录处理是否符合流程，再计算满意度和承办评级。

## 4. 政策、大纲与环境版本

政策实例包含公告日期、生效日期、作用对象、变更内容、适用届次与过渡规则。公告和生效是两个事件。

- 默认提前至少 30 个标准日公告重要资格、设备环境和大纲变化；不可抗力可例外并提供补偿或改期规则。
- 已开赛赛事使用锁定快照；已经公布的奖项不因普通政策更新追溯取消。
- 未开始的报名若受到政策影响，重新检查并告知替代方案；已支付费用的处理写入过渡规则。
- 大纲变化调整知识权重和后续题目分布，不直接把旧知识等级归零。
- 升学政策按毕业届次适用，不能让同一个学生在一天内切换两套资格规则。
- 新闻只传递已知内容。玩家“提前获悉信息”只缩短准备延迟，不允许利用未公开赛题。

每学年默认至多一个主要世界规则变化；其他可作为小幅市场和对手波动。历史快照保存当时规则包版本，便于理解多年成绩。

## 5. 竞争学校的有限模拟

第 6 阶段“长线与世界”接入完整 AI 学校：每个地区生成有限数量的学校，每所保存稳定 ID、规模、风格、预算、训练偏好、年级结构、声誉与目标。

第 3 阶段“完整赛季”先使用固定或预生成的对手快照，仍遵守参赛资格、同模型算分和赛前名单锁定；这一阶段不要求实现 AI 学校的持续经营。下表为第 6 阶段的完整模拟周期。

| 周期 | 模拟内容 |
|---|---|
| 每周 | 按资源和风格分配训练、休整与学业比例 |
| 每月 | 结算经费、设备和教学容量，检查招生成本与欠款 |
| 每赛季 | 报名、资格校验、同模型算分、退役与招生 |
| 多年 | 教练变更、世代起伏、联盟合作和扩建 |

AI 学校不需要渲染完整校园，仍必须遵守资金、日程、资格和培养年限。已存在的对手名单不能在比赛结束后按玩家成绩临时加强。

难度通过开局资源、候选池和计划质量调整；默认不提供运行中隐藏追赶加成。若以后加入动态辅助，应由玩家明确选择并显示在存档设置中。

挖角事件要有公开邀请、培养条件和学生意愿，不应由对手单次随机检定直接删除本校学生。联盟共享公开资源，不能绕过赛题保密和不可转让名额。

## 6. 内容制作清单

新增事件至少填写：触发目的、玩家可观察的先兆、可行选择、直接成本、延迟后果、冷却、目标消失回退、是否进入校史。

首轮事件可覆盖 8 类：高疲劳提醒、家长学业沟通、普通设备故障、赛前检查、差线复盘、学长讲座、赞助要求、承办换机。每类先做一条可完整闭环的链，再增加文案变体。

## 7. 验收场景

| 场景 | 应有结果 |
|---|---|
| 资金为 0 时触发设备事件 | 至少有错峰或休息等免费路径 |
| 事件打开后目标学生退役 | 转为退役后允许的分支或取消并记录 |
| 连续读取相同存档 | 待处理事件和随机顺序不变化 |
| 同日触发五个提示 | 优先级排序，普通提示进入通知中心 |
| 政策生效日在精简模式区块中间 | 在具体标准日期生效并中断相应计划 |
| 对手在上次比赛表现出色 | 由持久化训练与属性解释，不临时作弊加分 |

[地区生态](14-regions-and-season-ecology.md)描述六个虚构地区原型、对手风格与赛季；[特色场景](17-scenarios-and-difficulty.md)改变初始局面。地区、场景、难度和赛季政策分别版本化，不能将某个场景的额外援助静默加入所有地区。
