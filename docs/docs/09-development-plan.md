# 开发阶段与验收

[返回 README](../README.md) · [设计总览](01-game-design.md) · [技术设计](08-technical-design.md)

此路线图按依赖和可验证交付拆分，不表示已经开始或完成任何阶段，也不承诺发布日期。每阶段先证明核心行为，再扩大内容量。

## 1. 原型要回答的问题

1. 训练、休息与复盘是否形成清楚的取舍，玩家能否解释学生成长差异？
2. 比赛低分是否能分解为可行动的原因，而非只感到随机不公平？
3. 只用固定机房和少量学生，日程与结果反馈是否足够易懂？
4. 同一段模拟能否在倍速变化和存读档后保持一致？

长线传承、自由建造与全国赛事仍是设计目标，但不应成为验证第一周日常循环的前置条件。

## 2. 第一阶段：固定机房原型（MVP）

### 2.1 范围

| 类别 | 需要交付 |
|---|---|
| 场景 | 一个可选中学生的固定机房，可先用简化模型或平面占位 |
| 学生 | 10 名固定测试学生，包含不同学习力、基础知识、体力和细节水平 |
| 时间 | 四时段、暂停和各档倍速，按标准日期稳定推进 |
| 日程 | 分组讲课、指定练习、休息、夜间睡眠；冲突校验与未执行计划修改 |
| 成长 | 累计知识 XP、体力、疲劳、心情；显示主要收益因子 |
| 比赛 | 一场预配置传统题模拟赛，部分分、时间预算、基础挂分、赛后错因 |
| 存档 | 一个手动档、至少一份有效备份、日末自动档；恢复未完成计划 |
| 界面 | 学生列表与详情、日程、当前活动、成绩与讲评、基础设置 |

MVP 固定为标准模式；招生、学业动态、压力与倦怠事件、自由建造、完整经济、承办、学长网络、政策、AI 学校、联机和 Mod 后续再做。比赛需要的压力等尚未实现的属性采用固定测试值，不在此阶段动态结算。

知识点先使用 6 个：枚举、排序、前缀和、二分、基础搜索、背包 DP。依赖配置保持最小化；10 人名单至少覆盖“前置不足”“基础熟练”“高疲劳”“低细节”等情况。

模拟赛题包使用 3 道合成题，每题 100 分，覆盖签到、独立部分分、较难满分解法。它是引擎测试内容，不宣称符合 CSP / NOIP 正式题量与时长。正式四题示例仍见[比赛文档](04-competition-simulation.md)。

### 2.2 完成条件

- 新启动后，不查看开发工具即可给两个小组安排一周日程。
- 一组持续高强度、一组适当休息，结果与训练公式一致；不是所有情况下休息组都必须胜出。
- 不足机位、同一教师重复占用和学生日程重叠都能在确认前发现。
- 运行预配置模拟赛，得到合法的 0～300 分及逐题错因；无反馈过程中不泄露真实成绩。
- 可以根据报告安排一次针对性讲评，只结算一次知识收益。
- 中途存档、重新启动并读取，继续后与不中断运行的状态摘要一致。
- 相同输入分别用 1× 和 10× 推进，得到同样的模拟结果。
- 规则验证与交互走查都通过后，才进入完整赛季。

## 3. 后续阶段与依赖

| 阶段 | 新增内容 | 依赖 | 交付验收 |
|---|---|---|---|
| 2. 核心系统 | 天赋、完整知识图、讲评、设备采购与基础布置 | MVP | 天赋影响可解释，设备与机位约束生效 |
| 3. 完整赛季 | 正式 6 人开局、招生、学业、资格、赛历、划线、退役 | 阶段 2 | 从 9 月连续经营到次年 8 月，年级与奖项正确结转 |
| 4. 经营闭环 | 拨款、工资、预算、账本、贷款选项、软失败、基础事件 | 阶段 3 | 缺钱可恢复，费用与补贴不重复，风险有先兆 |
| 5. 承办与名额 | 资质、筹备、事故、分期预算、名额分配 | 阶段 4 | 一次认证考点从申请到归档可完整闭环 |
| 6. 长线与世界 | 学长、校史、政策、竞争学校、精简模式 | 阶段 3～5 | 多年运行无生命周期断裂，规则版本可追溯 |
| 7. 内容扩充 | 更多题包、天赋、事件链、外出活动、自办赛事 | 阶段 6 | 新内容通过统一 schema 与引用校验 |
| 8. 打磨与发布准备 | 美术音效、无障碍、性能、迁移、本地化、安装包 | 各系统稳定 | 目标平台完整游玩与升级恢复验证 |

基本存档和错误反馈属于 MVP，后期才做的是完善的迁移、版本兼容与发布体验。长期性能验证随数据增长持续开展，不能全部拖到发布阶段。联机、工坊与可执行 Mod 保持为独立后续议题。

## 4. 优先级与内容边界

- **P0**：时间不乱、日程不重叠、结果能解释、数据不丢失、费用奖励不重复。
- **P1**：学生差异、比赛复盘、经营恢复、赛季交接、可理解的事件链。
- **P2**：装饰、更多梗、罕见事件、回放分享、复杂镜头和品牌赛事。

大型承办、美术装饰和互动题型需要建立在 P0 稳定的前提上。内容数量不能替代完整的“操作—结算—反馈—下一步”闭环。

## 5. 验收场景矩阵

| 编号 | 场景 | 通过标准 | 最早阶段 |
|---|---|---|---|
| A01 | 固定种子跑一周训练 | 手算样例与模拟相符，属性有界 | MVP |
| A02 | 1× / 10× 相同计划 | 排除 UI 时间后状态摘要一致 | MVP |
| A03 | 模拟赛截止时尚未提交 | 草稿不计分，原因清楚 | MVP |
| A04 | 模拟赛中途存读档 | 继续后的提交与结果一致 | MVP |
| A05 | 重复点击讲评或奖励确认 | 幂等，不重复增益 | MVP / 奖励接入时 |
| A06 | 初三、高三跨年 | 按去向与资格推进，不重复升年级 | 阶段 3 |
| A07 | 同分奖项与固定晋级名额 | 分别按规则包处理 | 阶段 3 |
| A08 | 第一学年基础账本 | 排除选项支出时年末现金 32,000 | 阶段 4 |
| A09 | 全员离队且现金耗尽 | 保留或补足 3 人基础教学条件，可继续 | 阶段 4 |
| A10 | 承办 30 人、32 台有效电脑 | 备用机校验拒绝通过 | 阶段 5 |
| A11 | 补贴预拨与尾款重复触发 | 合计仅 15,000，账目可追溯 | 阶段 5 |

| A13 | 精简模式中途政策生效 | 准确停在标准日，余下计划可改 | 阶段 6 |

上表是未来实现的验收计划；当前只有文档，不能将这些场景标记成已通过的软件测试。

## 6. 平衡试验

先用固定种子和对照策略观察，再扩展到多种子。建议至少比较：均衡训练、持续高强度、过度休息、只刷熟题、集中培养一人、全员平均分配。

观测指标包括：知识成长、有效出勤、疲劳与倦怠、退队与毕业、比赛得分构成、现金最低点、保底援助次数和重复决策负担。

- 不预设某一种策略所有年份都最强，应由学生基础、赛季目标和资源条件改变选择。
- 如果持续熬夜始终最优，先检查睡眠替代成本与状态结算，再加随机惩罚。
- 如果多买设备就必然提高正式比赛得分，检查训练设备和正式评测环境是否混为一谈。
- 如果长期只依赖随机赞助才活得下去，先修正基础经费与支出结构。
- 如果一代天才带来永久垄断，检查拨款上限、招生分布与学长支援上限。

数值试验应记录配置版本、种子集合、策略规则与结果分布，避免只展示一次幸运的冠军案例。

## 7. 风险与验证动作

| 风险 | 可观察信号 | 优先验证 |
|---|---|---|
| 全年等待过长 | 大量时间在无事件推进 | 首周与首赛节奏、自动日程、精简模式观察频率 |
| 学生缺少个性 | 玩家只看综合分选人 | 分组差异、真实错因、目标与代际交接 |
| 比赛像随机抽奖 | 复盘无法改变下次安排 | 概率尺度、错误持续性、时间预算和原因报告 |
| 承办成刷钱工具 | 重复小比赛无风险盈利 | 工期、人员、资本支出和补贴结算 |
| 长线数据膨胀 | 存档或日志随帧数增长 | 年度聚合与稳定引用 |
| 范围失控 | 核心循环未闭环却增加大量系统 | 按阶段完成条件减少并行内容 |

## 8. 待定事项与默认假设

| 议题 | 当前默认 | 何时决定 |
|---|---|---|
| 目标平台与引擎 | 未选择，先验证纯模拟和最小场景 | MVP 工程初始化前 |
| 玩家是否只控制教练 | 默认只控制教练，不手操学生解题 | MVP 交互确认时 |
| 时间长度是否舒适 | 保留标准 / 精简设计，先做标准模式 | 首个完整赛季测试后 |
| 隐藏属性展示精度 | 正式模式先区间后收窄，调试可看真值 | 学生界面试用后 |
| 现实赛制与虚构程度 | 默认版本化游戏规则包 | 制作正式赛事内容前 |
| 非本校年级衔接 | 使用去向事件，不默认所有初中生直升 | 生命周期接入时 |
| 政策、升学、承办奖励 | 保持游戏抽象并注明适用规则 | 赛季与承办阶段 |
| 多语言、商业发布、授权 | 未确定 | 对外发布准备前 |

## 9. 文档维护与完成定义

新增系统需要写清：玩家决策、输入输出、成本、结算时点、异常回退、可见信息和验收场景。涉及费用、时间、资格或概率的修改，更新所属专题、总览引用和数字示例。

一项功能完成意味着正常路径与关键异常路径都能演示、结果可解释、保存恢复正确、界面不泄露隐藏信息。只有设计文档或单独的漂亮界面，不等同于系统已完成。

## 10. 扩展设计的接入矩阵

新增内容量不等于第一版范围。建议先从每个专题挑选一条能闭环的内容验证，再按依赖扩充；以下“首次”是可以开始接入的阶段，不表示该阶段要实现整份专题。

| 专题 | 首次接入 | 当阶段的最小切片 | 完整扩展的前提 |
|---|---|---|---|
| 课程教研 | 阶段2 | 六知识基础上补前置与一条路线 | 完整题库、熟题记录、课程验收 |
| 教师团队 | 阶段2 | 一位助教、独立精力与岗位 | 阶段4合同、薪酬、交接与制度 |
| 人物故事 | 阶段3 | 一个已绑定事实的诉求与复查 | 记忆承诺、cause_key、生命周期 |
| 校园后勤 | 阶段2 | 固定场地中的设备采购与有效机位 | 经营预算、施工、临时场地和服务 |
| 地区生态 | 阶段3 | 地区规则与固定对手快照 | 阶段6持续AI学校、联盟和世界变化 |
| 合作与品牌 | 阶段4 | 一份有限额、分期和交付的合同 | 人员工时、退款与项目预算 |
| 事件库 | 阶段3 | 两张状态卡与一个到期检查 | 阶段4～7按设施和世界能力扩展 |
| 特色开局 | 阶段3 | 标准新档外一份独立初值配置 | 不同场景的教学、财务与恢复验证 |
| 成就表达 | 阶段3 | 正式事实触发少量徽章 | 阶段6～8校史、本机档案、素材与导出 |
| 平衡实验 | MVP起 | 一周固定输入对照 | 随系统增长加入赛季与多种子 |
| 原创题目联赛 | MVP起 | 三题合成固定卷 | 阶段3四题/两天赛，阶段7组卷和联赛 |
| 视听制作 | MVP起 | 可读占位场景与基础提示 | 阶段8资产预算、混音、辅助设置 |
| 长期计划 | 阶段2 | 模板保存与展开 | 阶段3保护赛程，阶段4预算，阶段6多年委派 |
| 天赋个人成长 | 阶段2 | 少量单环节天赋 | 后续证据周结算、发现与曲线验证 |

### 10.1 推荐的内容制作批次

第一批只围绕“新学生理解前置—参加诊断—发现错因—调整计划”制作，优先把一周做完整。第二批加入“有预算的教师与设备—一个完整赛季—初三去向”，检验资源和生命周期。第三批才进入“承办、合同、地区对手、代际交接”。

每批都需要一份正常案例、一份资源不足案例和一份中途存读档案例。可以先使用[十二张题目卡](20-contest-content-and-tournament-design.md)、[三十张事件卡](16-event-library.md)中的子集，不必为了达到文档数量复制没有完成的内容。

### 10.2 本轮增加的关键检查

- 主机、显示器键鼠座椅、槽位和考场资质分别计数。
- 公开活动同时计备课、授课与场地，不把同一岗位工时卖两次。
- 人物故事与事件主卡共用诉求、承诺、冷却和主要事件额度。
- 暂停训练的正常返队与正式退役后的例外回归分开。
- 自动休整的滞回状态、当天重排次数和预算周期必须随档恢复。
- 永久能力证据以每人每标准时段为上限，不按活动拆分数或提交次数刷取。
- 跨剧本成就依赖独立世界的年度证据，复制存档不构成另一次开局。
- 纯装饰不提供训练加成，无反馈赛也不能从音乐、成就和截图泄露真分。

这些是未来实现的验收约束，当前文档检查只确认表述、引用和算例是否一致，不代表相关软件能力已经通过测试。
