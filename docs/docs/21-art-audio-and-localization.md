# 视听表现、环境叙事与本地化

[返回 README](../README.md) · [界面与引导](07-ui-and-onboarding.md) · [校园建设](13-campus-construction-and-logistics.md) · [玩家表达](18-achievements-and-player-expression.md)

本篇把“3D 像素风机房经营”展开为可制作、可复用的表现方案。资产数量与规格都是候选制作预算，仓库当前没有对应模型、音频或成品界面。美术表现优先解释状态和营造校队生活，不改变模拟结果。

## 1. 画面基调与空间记忆

核心场景应有“有人长年在这里学习”的感觉：机箱贴纸、褪色的赛程表、改过多次的白板、窗边水杯、毕业生留下的笔记。新旧物品共存比所有设备同时变豪华更能体现经营历史。

前期机房可以拥挤但清楚，后期扩建更整洁但仍保留几个熟悉角落。玩家能通过布局和物件记住某届学生，而非只靠年份面板认出存档。

不将贫穷表现为所有学生都灰暗、不把好成绩等同于唯一正确的生活状态。休息、讨论、失败后继续练习和普通毕业都应有完整表现。

## 2. 镜头与像素方案

候选方案为正交或接近正交的斜俯视镜头，四向旋转，房间可剖面。核心可交互物体必须在四个方向都能被识别，不能只有默认角度好看。

场景可先在 640×360 的虚拟画布上验证像素化，再放大到窗口；UI 使用独立的清晰分辨率绘制。这个分辨率只是美术试验起点，不是发布平台承诺。缩放允许离散档位，避免任意小数缩放使像素轮廓不停抖动。

表现层坐标、影子和镜头移动按统一规则对齐像素；交互命中使用世界或 UI 实际几何，不依靠模糊色块判断。建筑占格、通道和设备容量继承校园专题，不由模型大小重新决定。

## 3. 颜色与材质层级

| 用途 | 候选颜色 | 读感与使用限制 |
|---|---|---|
| 深色轮廓 | #26313A | 人物和设备的结构，避免大片纯黑 |
| 校园浅墙 | #E7DFCC | 中性背景，给状态图标留对比 |
| 木桌与纸张 | #B98557 / #F2E7CC | 日常温度与旧物感 |
| 屏幕冷光 | #6EA6BA | 表现电脑运行，亮度不能抢过通知 |
| 植物与休息 | #7D9A6C | 环境变化，不能单独作为健康指标 |
| 关注提醒 | #D4A44C | 普通风险，同时配图标和文字 |
| 紧急提醒 | #B85B57 | 真正阻塞的事项，限制闪烁使用 |
| 荣誉点缀 | #D9BC6B | 奖杯、照片框与纪念物，避免满屏金光 |

题目难度色、Rating 色与语义警报分开使用，不因为都叫“红色”就共用同一套解释。色盲模式用形状、标签与描边提供等价信息。

材质使用有限纹理与色阶。电脑升级可以改变机箱、屏幕和噪音，但不能让最贵设备发出遮挡学生状态的巨大光效。

## 4. 角色的组合与识别

角色在默认视角下约 16～24 像素高，优先分清发型、眼镜、衣着主色、书包和惯用位置。一个基础骨架可组合多套外观，少量独特配件留给可识别的学生故事与学长回校。

| 外观层 | 初期可做内容 | 数据与叙事约束 |
|---|---|---|
| 头部 | 4～6 种发型、眼镜与发夹 | 不由某种发型推断天赋 |
| 上装 | 初中校服、高中校服、运动服、卫衣 | 年级变化依日期与学校设定 |
| 下装 | 2～3 种基本轮廓和配色 | 以识别优先，减少遮挡 |
| 配件 | 水杯、背包、徽章、笔记本 | 纪念物可关联具体事件 |
| 学长 | 大学外套、工作装、旧校服纪念 | 由真实阶段变化解锁 |

外观生成独立于能力随机流。修改发型、校服或昵称不重新抽天赋，不为外观组合提供隐含强弱。重名学生通过档案和场景标记区分。

## 5. 动作状态与可中断动画

核心动作集包括：走路、坐下、打字、看板书、思考、举手、交流、伸展、喝水、收拾东西、欢呼、失落、睡眠。MVP 可只用走路、学习、休息和反馈四类占位状态。

- 活动开始以逻辑快照为准，不等待所有人播放完坐下动作才结算。
- 倍速提高时缩短或跳过过渡动作，不把打字动作播放次数当作练习次数。
- 角色被选中时暂停不了他人逻辑；选中描边不能改变任务优先级。
- 存档只需保留模拟活动与必要位置，不保存每一帧手指姿势。
- 换机、离队和场地改造后重新寻路；若路径被堵，先反馈阻塞，再给可行替代路线。

两名学生讨论可以触发对话动作，但关系变化来自实际活动结果，不能因站得近每帧无限加好感。

## 6. 气泡、情绪与隐藏信息

头顶只保留少量高优先级状态：当前活动、需要处理的风险、即时情绪。多人高密度时合并为小组摘要，选中后展开。

~~~text
正在想办法 → 主观行为
样例通过 → 已发生的本地自测
很有把握 → 学生主观判断
正式 AC → 规则已允许公开的评测结果
~~~

上述气泡不能混用。无反馈 OI 赛中不播放正式 AC 灯光、得分飘字或真实排名变化；即使计算已经在后台完成，也要等到解封边界。

压力和倦怠用动作与语言表达，而非强制显示污名化标签。睡着、揉眼和离席都只是线索，玩家点击后能看见实际原因与可采取的行动。

## 7. 房间套件与经营阶段

| 套件 | 常见对象 | 表现目标 |
|---|---|---|
| 旧机房 | 旧桌、杂色椅、风扇、白板、几台不统一主机 | 起步感，同时保有整洁和秩序 |
| 基础教学 | 投影、书架、题单板、资料角 | 让课程和复盘可见 |
| 稳定运营 | 布线、空调、备用机角、维修台 | 显示可靠性，不只是豪华 |
| 承办准备 | 指示牌、候考区、证件、隔离带、技术台 | 区分参赛与后勤区域 |
| 传承空间 | 照片、旧队服、奖杯、手写留言、毕业签名 | 让历史留在场景中 |

同一设施分为可交互核心与装饰外壳。服务器机柜的形状不决定评测容量，实际参数来自设备配置。装饰主题更换只更换表现；具备实益的设施升级要在采购页明确。

## 8. 昼夜、季节与天气

每天四时段通过光照、窗外、人员和环境音区分。夜间只留少数灯，睡眠在宿舍或离校状态表现，不应让所有角色每天都睡在机房座位上。

季节可以呈现春季窗外绿意、夏季空调与蝉鸣、秋季招生宣传、冬季衣物和霜窗。积雪和暴雨来自地区气候配置，不能所有地区每年都强制下雪。

天气影响若进入规则，先由[校园与后勤](13-campus-construction-and-logistics.md)定义出行、电力和环境效果；美术只读取已知天气。屏幕先出现暴雨不应提前泄露尚未决定的设备故障。

考试周布置横幅、候场证件和封闭区域；结束后按场地归还任务清理。场景可留下照片与纪念物，不永久堆满每一年的一次性宣传物。

## 9. 环境叙事的持久状态

建议保留有限数量的场景纪念槽：第一台电脑、第一张合照、一次承办标牌、毕业签名板等。超过展示槽时放入校史仓库，由玩家选哪些继续展出。

物件可以查看来源、年份和相关学生。删除展示不删除历史档案；出售普通设备前提醒是否有关联纪念记录，可以仅保留照片与铭牌。

本版旧物、奖杯与纪念槽只供展示，不提供训练系数或其他经营加成。若以后引入有数值效果的功能设施，应在设施采购与属性中独立定义，并同步修订玩家表达专题；不能把纯装饰作为隐藏的最优培养配置。

## 10. 声音的三层结构

| 层 | 例子 | 混音目的 |
|---|---|---|
| 持续环境 | 风扇、空调、远处操场、雨声 | 建立时间与房间感，长听不疲劳 |
| 行为细节 | 键盘、翻页、落座、白板笔、脚步 | 给学生动作重量，但限制同屏叠加 |
| 重要反馈 | 通知、公开评测、故障、结算、颁奖 | 帮玩家发现需要注意的信息 |

同屏几十人打字不应播放几十条同音量循环。可把远处学生合为机房底噪，选中学生和近景对象保留细节。音频聚合不影响实际设备与人物数量。

声音总线预留音乐、环境、反馈和可选语音独立音量；静音不丢失必要信息。使用耳机与小音箱都要能辨认重要提示。

## 11. 音乐状态与无缝切换

基础可准备六种氛围：平静日常、专注训练、休息夜晚、比赛进行、结果揭晓、年度回顾。进入某种音乐状态依逻辑阶段，不依玩家随机点开什么面板。

比赛音乐可有基础、紧张、最后检查三层。虚拟倒计时到预设里程碑时只触发一次层变化；暂停时保持或淡出，不继续累积音乐节奏带来的计时假象。

失利使用克制的情绪变化，不对普通低分播放灾难音效。年度回顾根据学校经历组合主题，但不能只允许夺冠存档有完整音乐和镜头。

长时间运行时避免短循环在相同位置重复强拍。变奏仅影响音频随机流，不能消耗事件和比赛随机数。

## 12. 音效清单与触发规则

| 音效 ID | 触发 | 去重与限制 |
|---|---|---|
| sfx_plan_confirm | 合法日程修改提交 | 一次批量提交一次 |
| sfx_action_reject | 操作被具体条件拒绝 | 连点合并，配文字原因 |
| sfx_local_compile | 本地编译完成 | 不代表正式通过 |
| sfx_sample_pass | 自测样例通过 | 无反馈赛允许，但声音区别于正式 AC |
| sfx_judge_accept | 正式评测公开为通过 | 只在有权知道时播放 |
| sfx_machine_fault | 已确认设备故障 | 同一实例一次，持续故障不循环报警 |
| sfx_notice_critical | 必须处理的截止或健康事项 | 与暂停通知同步，不每帧重复 |
| sfx_budget_received | 真实款项到账 | 应收合同签订不播放到账声 |
| sfx_yearbook_open | 打开年度纪念 | 可关闭，不能盖过对话 |
| sfx_award_confirmed | 最终奖项确认 | 临时榜单不触发 |

TLE、WA、RE 应有不同视觉标签，但不必每一种都强行搭配刺耳失败音。玩家可单独关闭重复评测提示。

## 13. 特殊场面的完整脚本

**第一次模拟赛**：入座与统一通知 → 倒计时开始 → 主观状态变化 → 截止收卷 → 简短等待 → 解封成绩 → 学生反应 → 进入讲评。玩家可跳过镜头，不能跳过实际时间预算和成绩锁定。

**毕业合照**：选择本届档案与合法合照对象 → 选择地点、排列、题字 → 生成一张纪念图与一条校史记录。退休或转学的学生能否出现依据其是否接受邀请，不把已经离校的人强制放回当前队伍。

**首次承办**：验收通过后的场地布置 → 开门入场 → 技术状态与现场服务 → 统一闭幕 → 归还场地。出现故障时切到可操作的状态界面，不连续播放不可跳过镜头阻止处置。

## 14. 中文排版与多语言准备

首轮内容以简体中文撰写。繁体中文和英文属于后续候选，不承诺同时交付。显示文本与稳定 ID 分离，学生名、赛事名、货币和日期采用不同字段，不拼接出难以翻译的半句。

角色气泡控制为短句，长说明进入详情。题目表格与资金数字用易比较的对齐方式，中文标点不被误切成孤立一列。OI 缩写保留鼠标或焦点说明，第一次出现时解释用途。

复数、单位、性别代词与姓名顺序尽量由完整语句模板处理。不要从某个中文名字推测人物性别后硬写叙事。玩家自定义文本过长时先预览折行，导出前可改短标题。

## 15. 动效与辅助设置

可关闭闪烁、震屏、红色边缘脉动、密集粒子和强烈镜头转场。开启减少动态效果后，仍通过静态徽标、进度和文字保留等价信息。

键盘焦点有清楚边框；状态变化不依赖悬停才可发现。关键消息在声音关闭、对比模式和 150% UI 缩放下仍可读取。提示停留时间可延长，模态抉择不会因玩家读得慢自动选不利选项。

照片与界面分享允许隐藏学生姓名、家长对话和自定义隐私文字；默认导出只含游戏数据和玩家明确选择的叙事内容，不带本机路径或存档文件位置。

## 16. 分阶段资产预算

| 阶段 | 最小资产包 | 不进入该阶段的内容 |
|---|---|---|
| MVP | 固定机房、占位学生、4类动作、基础UI、简短提示音 | 多校校园、毕业大片、全套季节皮肤 |
| 核心与赛季 | 学生组合、6种活动表现、成绩反馈、基础季节与场地 | 每条剧情专属全动画 |
| 经营与承办 | 设施升级、施工占位、候场套件、设备状态、会场提示 | 为每一种规模另造不可复用场景 |
| 长线与内容 | 学长外观、纪念物、照片模板、地区环境差异 | 自动生成无限唯一模型 |
| 发布打磨 | 完整混音、性能变体、无障碍设置、本地化检查 | 用未定数量的素材替代实际验证 |

每项资源记录 ID、用途、版本、制作来源、依赖和可替换层。占位资产能被正式资产替换而不改变碰撞与设施容量。复用相同角色骨架和房间套件，优先把预算花在玩家反复看到的画面。

## 17. 走查场景与验收

在同一机房里放置 6、20、50 名学生，分别检查选中、遮挡、头顶信息、音效叠加与帧率；承办观众使用更简化的表现，不让远处 NPC 抢过本校学生细节预算。

必须走查：四向镜头、昼夜、下雨、停电后的可读性、UI放大、关声音、减少动态效果、无反馈比赛、窗口缩放和长中文姓名。没有隐藏分数泄露，没有重要文本被像素化到无法辨认，才算表现方案完成。

具体性能数值等目标平台与基准机器确定后制定；在此之前报告实际测试环境与数据，不写无依据的“全平台60帧”。
