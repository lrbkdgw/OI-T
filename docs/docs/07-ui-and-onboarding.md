# 界面与新手体验

[返回 README](../README.md) · [训练规则](02-time-and-training.md) · [开发验收](09-development-plan.md)

界面优先帮助玩家回答“现在有什么问题、可选行动是什么、执行后发生了什么”。每个建议都给出原因和成本，减少依赖玩家记忆规则。

## 1. 主界面的信息层级

| 区域 | 常驻信息 | 点击后的目标 |
|---|---|---|
| 顶部资源栏 | 日期与时段、倍速、现金、教练精力、关键警报 | 进入对应日程、账本或风险明细 |
| 机房场景 | 谁在学习、休息、缺席，哪些设备不可用 | 选中学生、设备或当前活动 |
| 日程摘要 | 当前活动、下一活动、尚未解决的冲突 | 修改未执行的计划 |
| 通知中心 | 待决策、待确认、一般消息 | 从消息跳到相关对象 |
| 底部或侧边导航 | 学生、日程、比赛、经营、校史 | 打开职责清晰的面板 |

MVP 只显示学生、日程、模拟赛、存档和设置。未来功能按阶段接入，不在原型中摆放大量不可点击入口。

## 2. 页面职责与主要路径

### 2.1 日程

支持“选人 → 选活动 → 选知识点与难度 → 看收益与冲突预览 → 确认”。拖动会给出位置预览，确认前不扣费。

预览显示负责人精力、占用时段、参与者数量、可用机位、预计 XP 区间、体力与疲劳变化。隐藏属性影响的部分使用区间或描述，不泄露真实潜力。

模板记录意图与对象筛选条件，不直接复制旧学生 ID。例如“初二图论组”在新学年重新匹配，并对新成员提示前置不足。批量替换有变更清单，不能自动覆盖比赛或学业考试。

### 2.2 学生

列表展示姓名、年级、当前活动、状态摘要、近期趋势；详情区分事实、观察估计与隐藏线索。

优先呈现可行动信息：“疲劳 78，连续三段高强度”并提供“调整后续日程”。属性说明能追溯最近变化，不把十几个常驻数字全部堆在头顶。

### 2.3 比赛

报名卡显示资格、截止时间、席位、费用和日程占用。不能报名时显示具体缺项，例如“本名额仅适用于本赛季”，而非统一“条件不足”。

赛中严格按赛制显示信息，见[比赛模拟](04-competition-simulation.md)。无反馈 OI 赛只显示自测和主观进展；成绩页面在解封后显示各题、子任务、总分和错因。

### 2.4 经营与承办

财务页区分当前现金、应付款、应收款和预测，不把未来尾款显示成可立即消费的现金。

承办页按“门槛 → 任务 → 人员与日程 → 分期预算 → 比赛日 → 结算”展示。名额分配先筛合法候选，再提示竞争与关系影响。

### 2.5 校史

按学年聚合重要节点，可从学生跳到其代表赛季，也可从奖杯回到当时的成绩与规则。暂无数据时解释如何形成记录，不展示编造的占位荣誉。

## 3. 首月体验脚本

引导使用真实规则和固定教学种子，不暗中送分。玩家可以跳过，已经安排的计划继续生效。

| 阶段 | 玩家完成的动作 | 应观察到的结果 |
|---|---|---|
| 首日暂停 | 观察机房，打开两名学生，查看可用设备 | 不同基础与状态，需要不同安排 |
| 第 1～3 日 | 给基础组上一节课，再安排题单 | 前置与难度匹配改变成长收益 |
| 第 4～7 日 | 对比持续训练与休息后的效率 | 休息有长期价值，疲劳有明确来源 |
| 第 2 周 | 根据一次学业或状态提醒调整计划 | 提醒通向可执行的日程修改 |
| 第 3 周 | 进行一场预配置模拟赛 | 部分分、时间不足和挂分是不同原因 |
| 第 4 周 | 安排讲评、保存模板、查看月结 | 把比赛结果转换为下一轮计划 |

原型只覆盖第一周与一场模拟赛；首月脚本用于后续正式新档。第一月不强制借款或承办，不靠突然停电考验尚未教会的应急功能。

## 4. 暂停、提醒与回到现场

- 打开普通面板不强制暂停，可在设置中改变；重大抉择在安全逻辑边界暂停。
- 手动解除暂停时，若仍有必须处理的抉择，明确提示阻塞项。
- 切回游戏时显示“上次处理到哪里”，包括当前时段、正在运行的计划和待办。
- 风险解除后关闭对应警报，不对同一疲劳值每个时段重复弹窗。
- “跳到下一事件”按当前限速推进，遇到必须决策事项停下；不能跳过中间结算或报名截止。
- 调整倍速不清空进度，不在弹窗关闭后突然补跑积压的现实时间。

## 5. 可解释反馈

| 结果 | 最少解释 |
|---|---|
| 学习收益低 | 显示基础 XP、难度、前置、状态、教师等主要因子 |
| 学生心情下降 | 指向具体事件、超难课程或关系原因 |
| 模拟赛低分 | 区分不会、没写完、挂分、策略和事故 |
| 现金减少 | 对应账本交易，不用“其他支出”吞掉主要费用 |
| 承办申请失败 | 硬性缺项与竞争评分分别解释 |
| 推荐调整日程 | 给出影响对象、替换时段与机会成本 |

精确数值与未知信息的边界要一致。玩家可以看已知训练系数，但不能借解释面板查看尚未揭示的天赋 ID 或正式赛隐藏成绩。

## 6. 撤销与确认

未执行的排课编辑可以撤销；已结算的训练、已到账补贴、已开奖比赛不能用普通撤销回滚。读取旧档属于独立操作，明确显示将替换当前进度。

昂贵采购、解除合同、提前退役确认和覆盖存档显示对象及实际后果。普通翻页、筛选与小额可撤销排课不增加确认弹窗。

异常状态提供恢复路径：无可用电脑可转纸笔或休息；没有老师可自主复习；钱不足可取消可选计划；缺少配置的旧档应提示具体问题，不能让玩家停在无响应按钮上。

## 7. 无障碍与表现

- 颜色必须同时配文字或图标：难度、AC / WA、风险、Rating 不靠颜色单独表达。
- UI 缩放至少预留 100%～150%，文字不使用模糊的像素字体承担长段说明。
- 可关闭闪烁、屏幕边缘脉动和高强度镜头效果，比赛倒计时提供静态替代。
- 键盘可访问主要面板；空格暂停，数字键调速等为候选映射，文本输入时禁用全局快捷键。
- 镜头旋转、剖面和缩放不改变模拟；被遮挡角色可通过名单选中。
- 有音效信息应有视觉等价提示；切后台默认自动暂停，具体行为在设置中说明。

## 8. 界面验收

玩家无需阅读专题文档，就应能完成：给一组学生排课、理解收益偏低的原因、安排休息、参加模拟赛、定位主要失分、保存并继续游戏。

界面走查覆盖：缩放后不截断关键金额与日期；隐藏分数不泄露；免费回退路径可发现；任务通知能跳到正确对象；空名单、全部设备故障、跨年模板和已退役目标都能正常展示。
